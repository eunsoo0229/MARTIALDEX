MARTIALDEX — AI 질문 기능 (Google Gemini API) 구현

작업 일자: 2026-08-14 · 작성: Claude (개발 어시스턴트)

1. 목표 및 핵심 원칙

  • Claude/OpenAI가 아닌 Google Gemini API를 사용, 무료 등급 모델 우선.
  • API Key는 프론트엔드 코드에 절대 작성하지 않고 환경변수(.env)로 관리.
  • Electron 구조상 API Key가 렌더러 번들에 노출되지 않도록 메인 프로세스/IPC로 격리.
  • 기술 상세 페이지, 홈 화면 모두에서 AI 질문 가능. 현재 기술의 실제 데이터를 context로 전달하고, 데이터에 없는 내용을 공식 데이터인 것처럼 지어내지 않도록 지침을 건다.
  • 위험한 기술(관절기·조르기·타격 등)은 전문 지도자 감독이 필요하다는 안내를 포함.

2. 아키텍처 — Provider / UI 분리

UI (AiAskModal.tsx)
   ↓
useAiChat (대화 상태, 캐싱, 히스토리 관리)
   ↓
AiProvider 인터페이스 (provider.ts) — window.martialdex.askAi(...) 호출만 함
   ↓  (IPC: ai:ask)
electron/main.cjs → electron/gemini.cjs  ← API 키는 여기서만 존재
   ↓
Gemini REST API

렌더러는 절대 Gemini API를 직접 호출하지 않는다. electron/gemini.cjs가 메인 프로세스에서 process.env.GEMINI_API_KEY를 읽어 REST 요청을 보내고, 결과 텍스트만 IPC로 렌더러에 돌려준다. 다른 AI 벤더로 교체할 때는 provider.ts와 gemini.cjs만 바꾸면 된다.

4. 사용한 Gemini 모델

최초 구현 시에는 gemini-2.5-flash를 기본값으로 사용했으나, 실제 API 키로 테스트한 결과 해당 계정에서 2.5 세대 모델(gemini-2.5-flash, gemini-2.5-flash-lite)이 "신규 사용자에게 더 이상 제공되지 않음" 오류를 반환했다. Gemini API의 models 목록을 직접 조회해 최신 세대인 gemini-3.6-flash가 정상 동작함을 확인하고 기본값을 교체했다. GEMINI_MODEL 환경변수로 언제든 다른 모델로 교체 가능하다.

5. 구현한 AI 기능

  • 기술 상세 페이지: 무술/이름/한국어명/카테고리/포지션/설명/목적/원리/변형/방어/카운터/연결기술/ 관련기술·무술/태그를 컨텍스트로 전달.
  • 홈/헤더: 전체 무술 목록 기반 전역 컨텍스트.
  • 질문 입력, 전송 버튼, 사용자/AI 메시지 말풍선, 로딩 도트, 오류 배너, 빈 입력 경고, 대화 지우기.
  • 로딩 중 중복 요청 방지, 동일 질문 재전송 시 캐시된 답변 재사용(API 재호출 없음).
  • 최근 6턴만 API로 재전송해 무료 등급 사용량 관리.
  • 오류 코드별 안내: 키 없음 / 유효하지 않음 / rate limit(429) / 네트워크 / 타임아웃 / 서버 혼잡(503).

6. 테스트 중 발견하고 수정한 문제

① API Key 배치 실수. 사용자가 .env.example(커밋되는 템플릿 파일)에 실제 키를 입력함 → .env(gitignore됨, 앱이 실제로 읽는 파일)로 옮기고 .env.example은 빈 템플릿으로 복원.
② 마크다운 노출. 실제 응답에서 **굵게** 문법이 그대로 텍스트로 노출됨 → system instruction에 "마크다운 금지, 일반 텍스트만" 규칙 추가.
③ 메타 발언 유출. 가끔 "지침을 지켰는가? 네" 같은 자기 점검 문장이 답변에 섞여 나옴 → "답변 본문만 출력, 메타 설명 금지" 규칙 추가 + maxOutputTokens 1024→2048.
④ 서버 과부하 오류 노출. 503 오류 시 영어 원문이 그대로 노출됨 → "Gemini 서버가 일시적으로 혼잡합니다"라는 한국어 안내로 매핑.

7. 테스트 결과

tsc --noEmit, npm run build 통과. Playwright(Electron) 실기 테스트로 홈/기술 페이지 모달 오픈, 빈 질문 경고, 기술 컨텍스트 반영, 로딩 표시, 실제 Gemini 응답(3회 연속 안정적), 동일 질문 캐시 재사용(첫 요청 10.9초 vs 재요청 0.3초), 오류 후 재시도, 대화 지우기, 기존 기능(영상 임베드, 즐겨찾기, 검색) 회귀 확인 모두 통과. 빌드 산출물에 API 키/엔드포인트 문자열이 없음을 grep으로 재확인.

8. GEMINI_API_KEY 설정 방법

  1. https://aistudio.google.com/apikey 에서 무료 키 발급 (결제 등록 불필요)
  2. 프로젝트 루트에 .env 파일 생성 (.env.example 참고)
  3. GEMINI_API_KEY=발급받은키 입력 (필요 시 GEMINI_MODEL=gemini-3.6-flash 등으로 교체)
  4. npm run dev 또는 npm run electron으로 앱 재시작
